Bharat Life-Admin Agent: A to Z
1. Idhu enna

Oru WhatsApp number. User Tamil-la voice illa text anuppuvanga, agent adhai purinjikittu, paperwork task-a step by step mudichu tharum. Chatbot maari answer mattum sollaadhu, work track panni mudikkum.

2. User journey (example)

Ravi, 2nd year student, scholarship apply panna:

Ravi voice note: “Enakku BC scholarship apply pannanum”
Agent: speech-to-text, Tamil purinjikum, intent = scholarship application.
Agent kelvi: “Un family income certificate irukka? College ID irukka?”
Ravi photo anuppuvaan. Agent OCR panni details edukkum.
Agent checklist: “Ready: ID, marksheet. Missing: income certificate.”
Missing certificate-ku: “Inga apply pannu, ivlo fee, ivlo naal aagum” nu guide.
Agent deadline set pannum: “Last date 15th. 10th-ku remind pannuren.”
Form details auto-fill panni, Ravi confirm panna piragu submit steps tharum.
Status check reminders.
3. Ulla eppadi work aagum (pipeline)
User (WhatsApp voice/text/photo)
   ↓
[1] Input layer: speech-to-text, OCR, language detect
   ↓
[2] Understanding: LLM intent + entities extract
   ↓
[3] Agent brain (planner): task-ah steps-ah break pannum
   ↓
[4] Tools: knowledge base, checklist engine, form filler, reminder, doc store
   ↓
[5] Human-in-the-loop: user confirm
   ↓
[6] Output: Tamil text/voice reply + next step
   ↓
[7] Memory: task state save (Postgres)

5. Agent design (mukkiyam)

Single prompt-la ellam panna koodadhu. Structure:

Router: User enna venum nu decide pannum (scholarship / certificate / bill / general).
Task agents: Ovvoru task-ku oru focused agent, own checklist + rules.
Tools (function calling):
get_checklist(task)
extract_document(photo)
check_missing_docs(user_id)
set_reminder(date, message)
get_scheme_info(name)
State machine: Task status: started → docs collecting → ready → submitted → tracking → done. LLM state-ah decide pannadhu, code decide pannum. Idhu reliable-aa irukka mukkiyam.
Human-in-the-loop: Submit, payment, personal data share-ku munnadi user confirm. Zoho-vum idhe approach follow panranga.
6. Knowledge base (unga real moat)

LLM-ku scheme rules theriyadhu, so neenga curate pannanum:

Scholarship name, eligibility, documents, last date, official link
Certificate types, apply process, fee, time
Source: official government sites, manual-aa verify pannu
Ovvoru entry-ku last_verified_date vachchuko, outdated info thaan periya risk
Start: 10 scholarships + 5 certificates mattum, accurate-aa

RAG use pannu, aana answer-ku source link kudu. Hallucination ippadi control pannalaam.

7. Form filling (realistic)
Government portals-ku bulk API illa. Full automation first-la try pannadhe.
V1: Guided mode. Agent data ready pannum, user-ku “inga click pannu, idha paste pannu” nu step tharum, illa pre-filled PDF generate pannum.
V2: Where official forms PDF, auto-fill PDF.
V3: Browser automation, aana user consent + portal terms check pannitu.
8. Security (unga cyber security strength)
Documents encrypt at rest + in transit.
Minimum data store pannu, venaanda aadhaar number mathiri sensitive data store pannadhe, illa mask pannu.
User-ku “En data delete pannu” command.
Consent: first message-la clear-aa sollu, enna data, yen.
Access logs, rate limiting, prompt injection protection (uploaded document-la irukkura text-ah instruction-aa edukka koodadhu).
LLM-ku personal data anuppumbodhu minimize pannu.
Idhai marketing-la use pannu: “Un documents-ku safe.”
9. Tamil voice
Tamil-English mix (Tanglish) handle pannanum, real users ippadi thaan pesuvanga.
STT accuracy test pannu: 20 real voice samples collect pannu.
Reply: simple Tamil, short sentences. Voice reply optional.
Fallback: purila na “Marubadiyum sollunga” nu kelu, guess pannadhe.
10. Tech stack (final)
